# Hoodmin

[Türkçe](README.md) · [العربية](README.ar.md) · [English](README.en.md)

Hoodmin **لوحة مستقلة لإدارة الخوادم والوصول، متوافقة مع VpnHood** ومكتوبة بلغة Rust. ليست منتج VpnHood Manager الرسمي، ولا تعيد كتابة خادم VPN أو تطبيق العميل. يُستخدم برنامج التثبيت الرسمي الجاهز لتثبيت خادم VpnHood.

تجلب كل مؤسسة خوادمها الخاصة (BYOS). ينتمي كل خادم إلى مستأجر واحد فقط (tenant)، ولا توجد مجموعة خوادم VPN مشتركة بين المستأجرين. لا تمر حركة VPN عبر Hoodmin؛ يتصل العميل بخادم VPN مباشرة.

## الحالة

تعمل نواة البروتوكول ولوحة الإدارة متعددة المستأجرين. تم التحقق من التوافق مع VpnHood **9.0.856** باستخدام اختبارات توافق .NET الفعلية واتصال عميل بخادم بعيد. لم يكتمل تجهيز التوزيع للإنتاج أو التكافؤ الكامل مع Manager مغلق المصدر. راجع [سجل التحقق باللغة التركية](docs/dogrulama.md).

## الميزات المتاحة

- واجهة تركية وعربية وإنجليزية؛ اتجاه من اليمين إلى اليسار (RTL) للعربية، ومظهر فاتح وداكن مع زر الشمس والقمر.
- نظرة عامة، وخوادم، ومفاتيح وصول، وجلسات VPN، ومستخدمو اللوحة، وسجل تدقيق، وإعدادات الحساب.
- أدوار المدير (admin) والمشغّل (operator) والمراقب (viewer)؛ إدارة المستخدمين وكلمات المرور، وحماية آخر مدير نشط.
- تسجيل الخوادم والمجموعات؛ تعديل الاسم وعنوان IP أو FQDN ومنفذ TCP والمجموعة؛ وضع الصيانة. يتطلب تجديد بيانات اتصال الخادم تأكيدًا صريحًا مع منع إعادة استخدام التأكيد القديم.
- مفاتيح `vh://` المتوافقة مع عملاء VpnHood؛ إنشاء 1–100 مفتاح في العملية الواحدة، وإلغاء وتفعيل وتعديل الحصص والصلاحية جماعيًا، مع البحث وتقسيم الصفحات.
- حدود لحركة البيانات والأجهزة ومدة الصلاحية؛ تبقى قرارات إنهاء الجلسات محفوظة حتى يؤكد الخادم استلامها.
- عدادات ملخص مباشرة عبر SSE، وحالة الخادم، وتصدير الاستخدام إلى CSV، ونوافذ مساعدة سياقية.
- أمان PostgreSQL على مستوى الصفوف مع FORCE RLS، ومفاتيح خارجية تشمل المستأجر، وسجل تدقيق للإضافة فقط؛ Argon2id وAES-256-GCM وفحوص CSRF/Origin وتحديد محاولات الدخول.

## المعمارية والمستودع

تستخدم المنظومة Rust/Tokio/Axum وPostgreSQL/SQLx وLeptos لتوليد الصفحات على الخادم (SSR). تضيف شيفرة JavaScript صغيرة التفاعلات؛ لا يُستخدم WebAssembly أو hydration في المتصفح. ينهي Nginx اتصال HTTPS، ويستمع Rust على loopback فقط، وتتصل خوادم VpnHood بنقاط Hoodmin تحت `/api/agent/`.

- `crates/manager`: لوحة Hoodmin وواجهتها البرمجية وأوامر المشغّل المحلية؛ اسم حزمة Cargo هو `hoodmin`.
- `crates/protocol`: صيغ JSON والمفاتيح الخاصة بـ VpnHood والتحقق من إثبات العميل.
- `crates/paste-compat`: طبقة توافق تستخدم الماكرو pastey الذي تجري صيانته.
- `migrations`: مخطط قاعدة البيانات وسياسات المستأجرين.
- `scripts`: نصوص إعداد وملفات خدمات لحاويات اختبار Debian المخصصة.
- `tests`: اختبارات تكامل HTTPS/PostgreSQL/.NET فعلية إلى جانب اختبارات Rust.
- `work`: بيانات اختبار ومخرجات خاصة مستبعدة من Git. لا تنشر الأسرار.

وثائق إضافية باللغة التركية: [المعمارية](docs/mimari.md)، [الواجهة واللغات](docs/arayuz-ve-diller.md)، [المقارنة مع console](docs/console-karsilastirmasi.md).

## البناء والتحقق

بيئة التحقق هي Debian 13 وPostgreSQL 17. إصدار Rust **1.99.1** مثبت في `rust-toolchain.toml` والاعتماديات مثبتة في `Cargo.lock`. يلزم Rust/Cargo ومكتبات تطوير OpenSSL وأدوات البناء المحلية. تتطلب اختبارات المقارنة مع .NET أيضًا SDK 10 ومصدر `VpnHood-Current` في المجلد المجاور؛ هذه أدوات اختبار وليست طريقة تثبيت خادم VPN.

مسارات أدوات البناء في حاوية الاختبار:

```bash
export CARGO_HOME=/opt/vpnhood-toolchain/cargo
export RUSTUP_HOME=/opt/vpnhood-toolchain/rustup
cargo build --release --locked
cargo fmt --all -- --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo audit --deny warnings
```

يجب تثبيت `cargo audit` بشكل منفصل. نجحت آخر الاختبارات المسجلة: 13 اختبار Rust، واختبارات اللوحة الفعلية عبر HTTPS/PostgreSQL/.NET، و18 فحص HTTPS للمظهر واللغة. لا تمثل هذه النتائج ضمانًا أمنيًا شاملًا.

لا توجد حزمة `.deb` بعد. النصان `scripts/setup-test-manager.sh` و`scripts/setup-test-tls.sh` مخصصان لبيئات الاختبار المعزولة فقط؛ لا تعِد تشغيلهما عشوائيًا على تثبيت قائم. ينشئ نص TLS مرجع شهادات خاصًا وقصير العمر للاختبار، وليس حل شهادات للإنتاج. راجع [ملاحظات الوكيل العكسي على VPS](docs/vps-ters-vekil.md) للتثبيت الحالي، ولا تعطّل التحقق من الشهادات.

يُنشأ الحساب الأول بالأمر المحلي `create-account` أو `scripts/bootstrap-panel.sh TENANT_UUID`. يحفظ النص كلمة المرور الأولية العشوائية في `work/panel-admin.txt` بصلاحيات 0600، ولا يغيّر كلمة مرور قائمة. راجع سجل التحقق لمتطلبات `scripts/test-contract.sh` و`tests/test_panel.py` و`tests/test_preferences.py`. تستخدم اختبارات التكامل مستأجرين منفصلين.

## القيود والعمل المتبقي

- تُطبّق إعدادات اتصال الخادم يدويًا؛ لا توجد أتمتة SSH أو طابور مهام دائم.
- المجموعات لتنظيم الخوادم حاليًا؛ لم يُنفّذ توزيع الحمل أو مفاتيح المجموعات أو روابط المفاتيح (token URL).
- لا يحدّث تعديل IP/FQDN المفاتيح الثابتة الموزعة سابقًا؛ تستخدم المفاتيح الجديدة العنوان الحالي.
- لم تكتمل أتمتة ACME وواجهة الخطط وملفات التعريف وحدود السرعة ومفاتيح API للبوتات وحزمة Debian وإجراءات النسخ الاحتياطي وتدوير مفاتيح التشفير للإنتاج.
- يُنشأ المستأجر من سطر الأوامر المحلي. لا توجد واجهة تسجيل عامة أو إدارة للمنصة. يدعم المخطط عضويات متعددة، لكن اللوحة تستخدم المستأجر الافتراضي للحساب.
- لا تحتوي تقارير الاستخدام على معرّف فريد لكل تقرير؛ قد تسبب الانقطاعات نقصًا في الحساب، ولا يوجد ضمان للاحتساب مرة واحدة بالضبط. يعتمد تطبيق الحصص على فترات إرسال التقارير.
- يستخدم اختبار الاتصال البعيد `NullVpnAdapter`؛ لم يتم التحقق من حركة VPN الفعلية أو توجيه نظام التشغيل أو الحمل المستمر أو الأداء.

تميز [وثيقة المقارنة](docs/console-karsilastirmasi.md) بين ميزات console والمتطلبات المعمارية والتحسينات الاختيارية. إدراج ميزة لا يعني الموافقة على تنفيذها.

## الاسم وتوافق التثبيت

أصبح اسم المنتج وحزمة Cargo الرئيسية **Hoodmin**. يحافظ تثبيت الاختبار الحالي على اسم الملف التنفيذي والخدمة `vpnhood-manager`، وقاعدة البيانات `vpnhood_manager`، ومستخدم النظام `vhmgr`، وإعدادات `VHM_*` وملفات الارتباط `__Host-vhm_*`. يبقى مجلد المستودع باسم `VpnHood`. سيُعالج الانتقال إلى أسماء تثبيت Hoodmin أثناء إعداد حزمة Debian، مع الحفاظ على البيانات والمفاتيح. تشير تسمية VpnHood إلى البروتوكول والخادم والعميل المتوافق معها.
