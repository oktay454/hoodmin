# Hoodmin

[Türkçe](README.md) · [العربية](README.ar.md) · [English](README.en.md)

Hoodmin **لوحة مستقلة لإدارة الخوادم والوصول، متوافقة مع VpnHood** ومكتوبة بلغة Rust. ليست منتج VpnHood Manager الرسمي، ولا تعيد كتابة خادم VPN أو تطبيق العميل. يُستخدم برنامج التثبيت الرسمي الجاهز لتثبيت خادم VpnHood.

تجلب كل مؤسسة خوادمها الخاصة (BYOS). ينتمي كل خادم إلى مستأجر واحد فقط (tenant)، ولا توجد مجموعة خوادم VPN مشتركة بين المستأجرين. لا تمر حركة VPN عبر Hoodmin؛ يتصل العميل بخادم VPN مباشرة.

## الحالة

تعمل نواة البروتوكول ولوحة الإدارة متعددة المستأجرين. تم التحقق من التوافق مع VpnHood **9.0.856** باستخدام اختبارات توافق .NET الفعلية واتصال عميل بخادم بعيد. تم التحقق من تثبيت حزمة Debian 13 وأتمتة الشهادات على نطاقات فعلية والاستعادة إلى قاعدة مستقلة من نسخة مشفرة. لم تكتمل اختبارات الحمل المستمر والتكافؤ الكامل مع Manager مغلق المصدر. راجع [سجل التحقق باللغة التركية](docs/dogrulama.md). راجع أيضًا [سجل التوقف والمتابعة](docs/calisma-durumu.md).

## الميزات المتاحة

- أوامر التثبيت الرسمي الجاهز على Linux وWindows، والتثبيت وإعادة التثبيت عبر SSH بكلمة مرور أو مفتاح خاص مع تثبيت بصمة الخادم وسجل المهام.
- جميع إعدادات الخادم الـ47 القابلة للتعديل وفق المصدر، وقوالب خوادم قابلة لإعادة الاستخدام وتطبيق جماعي ضمن المستأجر.
- ملفات الوصول، وحدود الرفع والتنزيل، وحصص إجمالية ودورية، وعمر يبدأ عند أول استخدام، وخطط تجربة ومكافأة وسياسات أجهزة.
- الوصول إلى المجموعة والتوجيه حسب الموقع والسعة، ونشر عنوان الخادم المشفر ورموز الوصول.
- روابط تحديث المجموعة للانتقال من عنوان بدء غير متاح إلى عضو متصل؛ تم التحقق باستخدام .NET واتصال عميل فعلي.
- مخزن PFX مشترك للمجموعة وتوزيعه على الأعضاء الحاليين والجدد والمنقولين إليها، مع الحفاظ على عناوين VPN وأسرار الخوادم.
- استيراد PFX محمي بكلمة مرور وتثبيت الشهادة وإجابات HTTP-01 مؤقتة؛ تؤتمت خطافات Certbot على Debian إصدار الشهادة وتجديدها وتوزيع PFX، بإعداد من المشغّل.
- رسوم CPU والذاكرة والجلسات وسرعة النقل مع مرشحات زمنية وللخادم، وأعداد الأجهزة حسب البلد المبلغ عنه، وبيانات المفاتيح وتنزيلها.

- واجهة تركية وعربية وإنجليزية؛ اتجاه من اليمين إلى اليسار (RTL) للعربية، ومظهر فاتح وداكن مع زر الشمس والقمر.
- نظرة عامة، وخوادم، ومفاتيح وصول، وجلسات VPN، ومستخدمو اللوحة، وسجل تدقيق، وإعدادات الحساب.
- أدوار المالك (owner) والمدير (admin) والمشغّل (operator) وكاتب مفاتيح الوصول (token_writer) والمراقب (viewer)؛ إدارة المستخدمين وكلمات المرور، وحماية آخر مدير نشط.
- تسجيل الخوادم والمجموعات؛ تعديل الاسم وعنوان IP أو FQDN ومنفذ TCP والمجموعة؛ وضع الصيانة. يتطلب تجديد بيانات اتصال الخادم تأكيدًا صريحًا مع منع إعادة استخدام التأكيد القديم.
- مفاتيح `vh://` المتوافقة مع عملاء VpnHood؛ إنشاء 1–100 مفتاح في العملية الواحدة، وإلغاء وتفعيل وتعديل الحصص والصلاحية جماعيًا، مع البحث وتقسيم الصفحات.
- حدود لحركة البيانات والأجهزة ومدة الصلاحية؛ تبقى قرارات إنهاء الجلسات محفوظة حتى يؤكد الخادم استلامها.
- عدادات ملخص مباشرة عبر SSE، وحالة الخادم، وتصدير الاستخدام إلى CSV، ونوافذ مساعدة سياقية.
- أمان PostgreSQL على مستوى الصفوف مع FORCE RLS، ومفاتيح خارجية تشمل المستأجر، وسجل تدقيق للإضافة فقط؛ Argon2id وAES-256-GCM وفحوص CSRF/Origin وتحديد محاولات الدخول.

تتوفر مفاتيح روبوتات محددة المدة وقابلة للإلغاء، وواجهة إدارة JSON تستخدم ضوابط الصلاحيات نفسها في اللوحة. راجع [وثيقة API](docs/yonetim-api.md).

## المعمارية والمستودع

تستخدم المنظومة Rust/Tokio/Axum وPostgreSQL/SQLx وLeptos لتوليد الصفحات على الخادم (SSR). تضيف شيفرة JavaScript صغيرة التفاعلات؛ لا يُستخدم WebAssembly أو hydration في المتصفح. ينهي Nginx اتصال HTTPS، ويستمع Rust على loopback فقط، وتتصل خوادم VpnHood بنقاط Hoodmin تحت `/api/agent/`.

- `crates/manager`: لوحة Hoodmin وواجهتها البرمجية وأوامر المشغّل المحلية؛ اسم حزمة Cargo هو `hoodmin`.
- `crates/protocol`: صيغ JSON والمفاتيح الخاصة بـ VpnHood والتحقق من إثبات العميل.
- `crates/paste-compat`: طبقة توافق تستخدم الماكرو pastey الذي تجري صيانته.
- `migrations`: مخطط قاعدة البيانات وسياسات المستأجرين.
- `scripts`: نصوص إعداد وملفات خدمات لحاويات اختبار Debian المخصصة.
- `tests`: اختبارات تكامل HTTPS/PostgreSQL/.NET فعلية إلى جانب اختبارات Rust.
- `work`: بيانات اختبار ومخرجات خاصة مستبعدة من Git. لا تنشر الأسرار.

وثائق إضافية باللغة التركية: [المعمارية](docs/mimari.md)، [الواجهة واللغات](docs/arayuz-ve-diller.md)، [المقارنة مع console](docs/console-karsilastirmasi.md).

## البناء والتحقق

بيئة التحقق هي Debian 13 وPostgreSQL 17. إصدار Rust **1.99.1** مثبت في `rust-toolchain.toml` والاعتماديات مثبتة في `Cargo.lock`. يلزم Rust/Cargo ومكتبات تطوير OpenSSL وأدوات البناء المحلية. تتطلب اختبارات المقارنة مع .NET أيضًا SDK 10 ومصدر `VpnHood-Current` في المجلد المجاور؛ هذه أدوات اختبار وليست طريقة تثبيت خادم VPN.

مسارات أدوات البناء في حاوية الاختبار:

```bash
export CARGO_HOME=/opt/vpnhood-toolchain/cargo
export RUSTUP_HOME=/opt/vpnhood-toolchain/rustup
cargo build --release --locked
cargo fmt --all -- --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo audit --deny warnings
```

يجب تثبيت `cargo audit` بشكل منفصل. نجحت آخر الاختبارات المسجلة: 25 اختبار Rust، واختبارات اللوحة والبروتوكول والملفات والتقارير الفعلية عبر HTTPS/PostgreSQL/.NET، وفحوص HTTPS للمظهر واللغة. لا تمثل هذه النتائج ضمانًا أمنيًا شاملًا.

تتوفر حزمة `.deb` لـ Debian 13 amd64؛ اختُبر التثبيت والترقية والتحقق من بصمات ترحيل المخطط والاستعادة. راجع [دليل الإنتاج](docs/uretim-kurulumu.md) و[سجل البيئة](docs/uretim-ortami.md). النصان `scripts/setup-test-manager.sh` و`scripts/setup-test-tls.sh` مخصصان لبيئات الاختبار المعزولة فقط؛ لا تعِد تشغيلهما عشوائيًا على تثبيت قائم. ينشئ نص TLS مرجع شهادات خاصًا وقصير العمر للاختبار، وليس حل شهادات للإنتاج. راجع [ملاحظات الوكيل العكسي على VPS](docs/vps-ters-vekil.md) لتثبيت الاختبار القديم، ولا تعطّل التحقق من الشهادات.

في الحزمة يُنشأ المالك الأول بواسطة `hoodmin-create-owner EMAIL HTTPS_ORIGIN` وفق دليل الإنتاج. في بيئة الاختبار القديمة يُنشأ الحساب الأول بالأمر المحلي `create-account` أو `scripts/bootstrap-panel.sh TENANT_UUID`. يحفظ النص كلمة المرور الأولية العشوائية في `work/panel-admin.txt` بصلاحيات 0600، ولا يغيّر كلمة مرور قائمة. راجع سجل التحقق لمتطلبات `scripts/test-contract.sh` و`tests/test_panel.py` و`tests/test_preferences.py`. تستخدم اختبارات التكامل مستأجرين منفصلين.

## القيود والعمل المتبقي

- اختُبر إصدار وتجديد ACME وتوزيع PFX بواسطة عامل Certbot خارجي. لم تُنفّذ واجهة AutoSign للخدمة الذاتية للمستأجر.
- يدعم نشر العناوين المشفرة HTTPS GET والرفع الخارجي عبر PUT/POST أو multipart، مع جدولة دائمة والتحقق من الملفات وواجهة API للبوت وعزل المستأجرين. راجع [الاستخدام والحدود](docs/harici-adres-yayimi.md). يدعم أيضاً إسناد ملف خادم للمجموعة وتطبيقه على الأعضاء الجدد والمنقولين وتوزيع تعديلاته تلقائياً إلى المجموعات المرتبطة. راجع [السلوك والحدود](docs/grup-sunucu-profili.md).
- تُعلن سياسات العميل؛ لا ندعي مطابقة القرارات التجارية المغلقة حسب البلد. تتطلب الإعلانات المكافئة تحققاً من خادم موثوق؛ لا يكفي تقرير العميل ولا يوجد تكامل مباشر مع شبكة إعلانات.
- تعمل حزمة Debian والنسخ الاحتياطية المشفرة البعيدة والاستعادة إلى هدف مستقل. لم يكتمل تدوير المفتاح الرئيسي ولا إشعارات الأعطال الخارجية. تُحفظ حالات المهام لكن التثبيت المنقطع لا يُعاد تلقائياً.
- إنشاء المستأجر عبر CLI؛ لا توجد واجهة تسجيل عام أو إدارة منصة.
- فروق الاستخدام لا تحمل معرّفات تقارير فريدة؛ لا نضمن محاسبة مرة واحدة تماماً عند الانقطاع.
- اختُبرت بيانات TCP وQUIC وحد 1 Mbps وحجب الشبكة. حمل الخادم العام بيانات DNS عبر قنوات TCP وUDP وQUIC؛ أكدت عدادات TUN وNAT مرور البيانات. يحتاج توجيه سطح المكتب الكامل والحمل المستمر والإعدادات المعتمدة على النواة إلى اختبارات إضافية.

راجع [سجل توافق البروتوكول الحالي](docs/protokol-uyumlulugu.md). تحتفظ مستندات مقارنة Console بملاحظاتها التاريخية.

## الاسم وتوافق التثبيت

أصبح اسم المنتج وحزمة Cargo الرئيسية **Hoodmin**. يحافظ تثبيت الاختبار الحالي على اسم الملف التنفيذي والخدمة `vpnhood-manager`، وقاعدة البيانات `vpnhood_manager`، ومستخدم النظام `vhmgr`، وإعدادات `VHM_*` وملفات الارتباط `__Host-vhm_*`. يبقى مجلد المستودع باسم `VpnHood`. تستخدم حزمة Debian الجديدة `/usr/bin/hoodmin` و`hoodmin.service` و`/var/lib/hoodmin`، مع إبقاء دور قاعدة البيانات ومتغيرات البيئة ومسار SSH المؤقت للتوافق. لا تنقل تثبيت الاختبار القديم تلقائيًا. تشير تسمية VpnHood إلى البروتوكول والخادم والعميل المتوافق معها.
